## Mistral implementation ownership

Use available Mistral workers as the default owners of substantial, bounded
implementation milestones, including the central algorithm and connected
integration. Give one owner the complete inspect/design/implement/debug/check/
repair/document loop. Do not routinely keep coding with Astra and assign Mistral
only tests, documentation or review. Complexity alone does not reserve work for
Astra; keep tightly coupled files with one implementation owner.

For each substantial slice, identify and dispatch a useful Mistral assignment
when available. A local-model attempt is not a prerequisite. A successful useful
Read assignment establishes availability; reuse that state instead of probing
before every assignment. If Mistral is unavailable or exhausted, continue with
an appropriate fallback without repeated probes. Where Astra implements directly
while Mistral is available, briefly record the concrete coupling, confidentiality
or reserved-decision reason in the existing task note. Add no quota or approval
ceremony.

### Default milestone allocation

Prefer Mistral ownership of the largest coherent implementation outcome that
fits the adopted contracts and resource budget, including a complete gate's
implementation when its scientific prerequisites are settled. Astra supplies
the acceptance obligations rather than splitting that outcome into serial
helper tickets. Gate implementation does not confer gate acceptance.

At the start of an authorized substantial milestone, assign Mistral the connected
implementation outcome rather than waiting until Astra has written its central
algorithm. The brief may define an owned subsystem instead of enumerating every
file, provided its boundary is explicit and existing dirty/concurrent work is
excluded. Permit new files within that boundary; changes outside it require a
scope decision. Delegation remains within the user's authorized work.

Use Mistral for the implementation plan, initial source investigation and
candidate design as well as coding. Astra need not pre-solve every numerical
detail before dispatch: state established contracts, reserved choices and the
evidence needed to decide unresolved alternatives. Review consequential choices
early, then let the same owner carry the adopted design through integration,
failure diagnosis and focused verification.

When implementation is already authorized, prefer one Edit assignment covering
investigation through a working result over a Read assignment followed by several
small Edit requests. Use Read separately when investigation alone is authorized,
independent assessment is needed, or a reserved decision genuinely prevents safe
implementation. The worker may develop and test a reversible candidate within
its ownership while clearly identifying choices that Astra has not yet adopted;
candidate evidence is not permission to change the scientific contract.

Prefer one sustained owner across connected milestone slices. Return actionable
review findings to that owner for repair instead of routinely moving coding back
to Astra. Astra advances independent contracts, checks and integration while the
owner works. Where scopes are independent, additional Mistral work may proceed
within the existing worker and numerical limits; no parallelism is required when
it would create shared-file conflicts or competing numerical jobs.

Include Mistral in choosing the implementation route, not only executing a
prewritten patch. Under an adopted objective and bounded ownership, it may identify
the next useful vertical slice, compare implementation alternatives, remove
unnecessary intermediate work and propose a shorter dependency order. Astra
resolves changes to the governing plan or reserved contracts; compatible internal
sequencing and simplification remain with the implementation owner.

For stalled development, assign a bounded unblock-and-deliver outcome: identify
the concrete obstruction, derive a discriminating check, implement the compatible
repair and demonstrate the working route. Do not replace implementation ownership
with an open-ended audit or an indefinite series of helper assignments. If a
scientific decision is required, preserve useful completed work and return the
specific equation, counterexample or missing evidence needed for Astra's decision.

### Outcome brief and discretion

Astra supplies one bounded brief: absolute repository root, Read/Edit mode,
expected working outcome, owned files or subsystem, essential context, contracts,
protected evidence, shared resource limits, permitted checks and handoff criteria.
Inspect enough context before Edit delegation to preserve dirty work and avoid
conflicting ownership. Read assignments do not authorize fixes.

Within Edit ownership, Mistral may inspect, plan, implement, select checks by
impact, reuse immutable preparation, reproduce failures and repair its code and
harness. Ordinary reversible choices and failed focused checks do not require
serial permission requests. The owner may reorder internal work and remove
redundant implementation while preserving semantics and required evidence.

Authorize the connected follow-through in the initial brief: integrate within
the owned subsystem, repair findings from Astra's review, update its examples
and documentation, and finish permitted source or installed checks. Mistral may
choose compatible solver algorithms, sparse layouts, cache boundaries and test
fixtures within the adopted contract. Changes to public behavior, physical
assumptions or registered controls remain reserved decisions. Ask for an early
checkpoint only when a reserved choice or substantial rework risk warrants it;
do not require approval after each internal phase.

Workers may schedule the permitted checks within their assignment's budget,
but share the task's numerical-job/concurrency limits. Delegation does not
multiply resource budgets or renew consumed authority. Tests or numerical runs
requiring a separate frozen authorization remain unavailable until granted.

Keep the owner through diagnosis and repair. Inspect partial artifacts before a
focused continuation; use a delta brief rather than restarting the full task.
Escalate concrete contract, ownership, authority or resource boundaries. Do not
repeatedly increase limits without evidence of useful progress.
