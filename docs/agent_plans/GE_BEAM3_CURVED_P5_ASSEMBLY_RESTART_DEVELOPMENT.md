## Validation and atomic state visibility

Canonical ASCII JSON uses sorted keys, fixed separators, a final newline and
finite values only. Duplicate keys, noncanonical bytes, nesting above 32,
payloads above 16 MiB, unexpected keys, coercible but wrong scalar types,
wrong counts/shapes, mismatched identities and hashes are rejected. The byte
bound is explicit for assembled records; the old one-element 1-MiB bound is
unchanged. Metadata cannot import code or select mechanics.

Restore constructs a fresh isolated model. Epoch-zero records must exactly
match its stress-free state. For accepted records, epoch linkage and exact
committed/accepted geometry/load bytes are checked, including signed zero.
Shared rotations must pass the unchanged frame validity checks. Every element
is reconstructed using accepted origins and saved local unknowns; the existing
local stability, stationary residual, scatter, global equilibrium, clamp and
station-order checks are applied. Reconstructed station histories must match
the committed histories. Neither local nor global Newton is invoked.

Only after all checks and allocations succeed is the staged checkpoint set and
the fresh model returned. Failure at the final element leaves caller-owned
objects untouched. Export uses the same full restore validation, rejects
pending trials and catches malformed private state before publication. Returned
committed state remains a defensive copy. This does not implement concurrent
model editing or a production restart service.

File publication validates first, stages in the target directory, flushes and
fsyncs, then creates the target by an exclusive hard link. Existing targets
are never overwritten. Unsupported publication fails closed and ordinary
failure cleanup removes only its own staging file. No directory-metadata
power-loss durability claim is made; abrupt termination may leave staging.
