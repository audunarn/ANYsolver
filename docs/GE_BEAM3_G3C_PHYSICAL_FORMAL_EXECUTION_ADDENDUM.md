## 2. Formal work-unit model

The current one-assignment/one-interpreter mapping is not the formal execution
model. Repeated Python, pytest, manifest and authority startup is an execution
artifact, not scientific independence. Formal execution uses two typed work
units while preserving every existing assignment and result:

1. A **history producer** owns one registered case, constructs one fresh owner,
   executes the complete command program once, performs all existing per-stage
   `native_checks`, accepted-pose diagnostic checks, station/recovery checks,
   directional check and MO08 transport/rebase checks, and exclusively writes
   prefix 0 through final plus the uninterrupted-final packet.
2. A **prefix replay shard** owns one registered case and a frozen contiguous
   prefix range. For each prefix in its range it reads and authenticates the
   producer packet, performs complete constructor-free preflight, creates a new
   owner with a separate call to `resume`, genuinely continues every remaining
   command, and requires exact full checkpoint bytes equal to the producer's
   uninterrupted final packet. The owner is discarded before the next prefix.

Fresh prefix import means a fresh authenticated `resume` construction and fresh
owner for every one of the 3,450 prefixes. It does not require a fresh operating
system process. A shard must not share owners, replayed numerical states, solver
results or mutable arrays between prefixes. It may share only immutable Python
modules, the hash-verified common manifest, and read-only producer packet bytes.
Any owner reuse, suffix-result cache or comparison of selected fields instead of
full bytes is a process defect.

The canonical scientific aggregate remains assignment-neutral and preserves the
existing exact formal ordering: 375 history records followed by all 3,450 prefix
records. Each record binds its original assignment index and exact assignment.
Grouping is visible only in the process receipt. Thus a change in shard layout
cannot change or reorder scientific evidence.

manifest descriptor and its own immutable assignment identity before every

finalization. No lease contains an independently editable copy of the common
input graph.

Producer output schema
`GE_BEAM3_G3C_PHYSICAL_FORMAL_HISTORY_SHARD_SCIENCE_V1` contains exactly one
history record and prefix packet descriptors. Replay output schema
`GE_BEAM3_G3C_PHYSICAL_FORMAL_PREFIX_SHARD_SCIENCE_V1` contains exactly the
assigned prefix records. Common scientific records contain IDs, exact errors,
booleans, hashes and registered enums only. Timings, PIDs, paths and resource
measurements remain in process records. Every child directory is closed-world;
all canonical files use strict ASCII JSON, reject duplicate keys and nonfinite
values, and are created exclusively.

The coordinator verifies every producer before dispatching its dependent replay

gap or duplicate. It recomputes the science from child files, writes a staged
