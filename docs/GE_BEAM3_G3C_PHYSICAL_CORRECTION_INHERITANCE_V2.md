## Captured-lease join

Before pytest or any numerical construction, the worker independently validates
the clean candidate, complete tracked-input DAG, implementation review, exact
assignment and exact correction-compatibility record.  It then captures those
same canonical lease bytes through both the unchanged private physical authority
module and the correction-only one-shot lease-binding module.

The correction-only module stores only the full lease SHA-256 and the SHA-256 of
the embedded compatibility record.  A correction replay must
require its supplied record to equal that captured fingerprint.  A structurally
valid or self-rehashed foreign record is therefore rejected, including changes
to successor commit, tree, review, runtime, unchanged-input digest, or allowed
paths.  Capture is one-shot and occurs only after the worker has independently
validated the complete lease against its clean Git/input/review authority.
Calls before capture, leases without correction authority, and normal
non-correction replay cannot obtain compatibility.

## Immutable dual-runtime comparison

The inherited checkpoint is first validated byte-for-byte and preflighted under
the frozen predecessor runtime.  Replay is constructed only under the captured
successor runtime.  On completion, the implementation compares an authenticated
view of the successor checkpoint with the predecessor bytes after replacing
only the view's top-level runtime identity with the frozen predecessor identity.
Neither source byte string is modified, republished, or admitted as successor
evidence.  Every other key and value must remain exactly identical and canonical.
Normal replay retains direct byte equality.

## Registered correction tests and schemas

Each of the two already-registered preflight assignments selects three tests:

1. the four successor-schema pre-construction rejections;
2. compatibility-record mutation rejections; and
3. one positive old-packet/new-runtime replay.

These tests add records inside the existing assignment nodes; they do not add or
renumber scientific assignments.  The positive record binds the predecessor and
successor runtime identities, input packet hash, and successor replay hash.

Correction aggregate, receipt, process, result, and node schemas require exact
key sets and exact scalar types.  Boolean, integer, and floating-point values are
never interchangeable.  The correction-union publisher performs a final full
authority check after staged validation and immediately before exclusive
promotion of the accepted evidence.  No accepted file may exist if this final
check fails.
